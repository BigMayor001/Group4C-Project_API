# Notes API (Group 4C)

A small REST API built with **Express.js** that lets users **create, retrieve, update and delete text notes**. Notes are stored in memory (no database), so data resets whenever the server restarts.

> Group project for BeTechified Backend Project (Week 4).

## Getting Started

### Prerequisites

- [Node.js](https://nodejs.org/) v18 or higher
- npm
- [Postman](https://www.postman.com/) (optional, for testing)

### Installation

1. Clone the repository:
   ```bash
   git clone https://github.com/BigMayor001/Group4C-Project_API.git
   ```
2. Move into the project folder:
   ```bash
   cd Group4C-Project_API
   ```
3. Install dependencies:
   ```bash
   npm install
   ```
4. (Optional) Create a `.env` file in the project root to change the port. If you skip this, the server uses port 5000:
   ```
   PORT=5000
   ```
5. Start the server:
   ```bash
   node App.js
   ```
6. The API runs on `http://localhost:5000` (or the port in your `.env`).

> **Mac users:** macOS uses port 5000 for AirPlay Receiver. If requests return `403 Forbidden` with no body, turn off **System Settings → General → AirDrop & Handoff → AirPlay Receiver**, or set a different `PORT` in your `.env`.

## Note Object

| Field | Type | Description |
| --- | --- | --- |
| `id` | number | Unique ID, generated by the server |
| `title` | string | Title of the note |
| `content` | string | Body text of the note |

Example:

```json
{
  "id": 1,
  "title": "Shopping list",
  "content": "Milk, bread, eggs"
}
```

## API Endpoints

Base URL: `http://localhost:5000`

| Method | Endpoint | Description |
| --- | --- | --- |
| GET | `/` | Welcome message listing the available endpoints |
| POST | `/notes` | Create a new note |
| GET | `/notes` | Get all notes |
| GET | `/notes/:id` | Get one note by ID |
| PUT | `/notes/:id` | Update a note |
| DELETE | `/notes/:id` | Delete a note |

### 1. Create a note

**POST** `/notes`

Request body:

```json
{
  "title": "Meeting notes",
  "content": "Discuss project deadline on Thursday"
}
```

Response `201 Created`:

```json
{
  "id": 1,
  "title": "Meeting notes",
  "content": "Discuss project deadline on Thursday"
}
```

### 2. Get all notes

**GET** `/notes`

Response `200 OK`:

```json
[
  {
    "id": 1,
    "title": "Meeting notes",
    "content": "Discuss project deadline on Thursday"
  }
]
```

Returns an empty array `[]` if there are no notes.

### 3. Get one note

**GET** `/notes/:id`

Response `200 OK`:

```json
{
  "id": 1,
  "title": "Meeting notes",
  "content": "Discuss project deadline on Thursday"
}
```

### 4. Update a note

**PUT** `/notes/:id`

Send `title`, `content`, or both. Fields you leave out stay the same.

Request body:

```json
{
  "content": "Deadline moved to Friday"
}
```

Response `200 OK`:

```json
{
  "id": 1,
  "title": "Meeting notes",
  "content": "Deadline moved to Friday"
}
```

### 5. Delete a note

**DELETE** `/notes/:id`

Response `200 OK`:

```json
{
  "message": "Note deleted",
  "note": {
    "id": 1,
    "title": "Meeting notes",
    "content": "Deadline moved to Friday"
  }
}
```

## Error Responses

| Status | When | Example body |
| --- | --- | --- |
| `400 Bad Request` | `title` or `content` is missing, empty, or not a string | `{"errors": ["title is required", "content must be a non-empty string"]}` |
| `400 Bad Request` | `PUT` with neither `title` nor `content` | `{"errors": ["Provide title and/or content to update"]}` |
| `400 Bad Request` | Request body is not valid JSON | `{"error": "Invalid JSON in request body"}` |
| `404 Not Found` | No note with that ID | `{"error": "Note with id 5 not found"}` |
| `404 Not Found` | Route does not exist | `{"error": "Route not found"}` |
| `500 Internal Server Error` | Unexpected server error | `{"error": "Something went wrong"}` |

## Testing with Postman

1. Start the server with `node App.js`.
2. For `POST` and `PUT` requests, set the body to **raw → JSON**.
3. Try the endpoints above in order: create, get all, get one, update, delete.
